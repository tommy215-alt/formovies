## 基本情報

| 項目 | 内容 |
|------|------|
| チャンネル名 | **リバース**（2026-10-26 にユーザーが指定。第 1〜2 話の時点の名前は「世界の解剖室」） |
| タグライン | **世界の仕組みを、はじめから。** |
| 旧キャッチコピー | 見えない仕組みを、CGで解き明かす。（第 1〜2 話） |
| 形式 | YouTube Shorts（縦型 9:16） |
| 尺 | 60〜90 秒を基本。テーマに応じて最適な長さを判断する |
| 出演 | **オモテ**（M・男性・破天荒な実験台）と **ウラ**（W・女性・毒舌の解説者）の 2 人（`CHARACTER_GUIDE.md`） |
| ターゲット | 20 代半ばを中心とした社会人 |

## 基本構成（第 3 話・pilot_006 以降）

「疑問を出して、キャラクターが解説する」形式をやめ、次の流れにする。

**疑問が生まれる → オモテがその疑問に関連した現象に巻き込まれる → とんでもない事態になる → ウラが毒舌を交えながら仕組みを解説する → オモテが理解する、あるいはさらにひどい目に遭う**

- 視聴者を最初に引き込むのは **出来事**、最後まで見せるのは **キャラクターと謎の解明**、見終わった後に残すのは **知識**。
- コメディと知識を別々に置かない。オモテが巻き込まれる出来事そのものを、仕組みの理解につなげる。
- ただし、現実の科学的事実をコメディの都合で歪めない。演出上の誇張（ギャグ・非現実の演出）は画面に明記し、現実の現象と区別する。
- テンポは第 2 話の約 1.3 倍を目安（話速と間で調整。重要なオチや発見の直前には短い間を残す）。
- **テクノ系の CG エンタメ**（2026-10-26 改修）：
  - BGM はテクノ／エレクトロニック（BPM 125〜150、4 つ打ちの重いキック、硬いシンセ、うねるベース）。軽いポップ・子ども向け・安っぽいコミカルな音楽にしない。笑いは映像と効果音の組み合わせで作る。
  - BGM は場面で変える：冒頭＝強烈な立ち上がり、巻き込まれ＝疾走感、解説＝存在感を抑えてリズムは維持、重要な事実＝一瞬音を引いて低音、オチ＝直前に止めて短いアクセント、エンディング＝整理してナレーションとロゴを立てる。
  - **冒頭 3 秒**：0〜0.5 秒でいきなり異常事態（カメラの急接近・旋回）、0.5〜1.5 秒で映像と効果音のインパクト、1.5〜3 秒で疑問を叩きつける。タイトルだけ・ロゴだけ・長い説明で始めない。毎回同じ爆発を使い回さず、テーマに合った現象にする。
  - テンポは第 3 話の初版のさらに約 1.3 倍（話速・間・重複の削除で）。
  - 映像は明るいまま（暗くしない）、白〜淡い寒色の地に水色の発光・格子・四隅の枠。カメラは場面ごとの寄り＋衝撃のパンチズーム。場面の切り替えは光の筋のワイプ。
  - 画面に出る人型のキャラクターは **オモテだけ**（3D ピクトグラム）。ウラは声だけ（`CHARACTER_GUIDE.md`）。

## 目的

日常生活・科学・テクノロジー・自然・歴史・社会などで、普段は意識しない仕組みを
CG・3D アニメーション・図解で可視化する。

見終えた視聴者に、次のどれかを感じてもらうことを目指す。

- 「なるほど、そういう仕組みだったのか！」
- 「えっ、そんなことになっていたの？」
- 「このチャンネルの別の動画も見てみたい！」

## 作り方の原則

1. **雑学の羅列にしない。** ひとつの疑問を出発点に、原因と結果をつなぎ、最後に納得できる答えを出す。
2. **1 本 1 疑問。** テーマは広く扱うが、各動画はひとつの疑問に集中する。
3. **映像にも情報を持たせる。** ナレーションを聞かなくても、映像だけで「何が起きているか」がある程度わかるようにする。
4. **見えないものを見せる手法**を使い分ける。
   - 断面・透視（物体の内部を見せる）
   - 逆再生（結果から原因へさかのぼる）
   - 条件を変えたシミュレーション（「もし〜がなかったら」）
   - 比喩 CG（データを小包に見立てる等）。※比喩であることが伝わるように演出する
5. **正確性は面白さと同じくらい重要。** 詳細は `FACT_CHECK_POLICY.md`。

## 扱うテーマ

- 日常に隠れた仕組み
- インターネットや情報技術
- 科学・物理・数学
- 人体や生物の仕組み
- 自然現象
- 物流・交通・インフラ
- 歴史的な発明や技術
- 社会を動かすシステム
- 直感と異なる現象や意外な事実

## テーマ選定の基準

| 基準 | 確認すること |
|------|-------------|
| 検証可能性 | 公的機関・規格・論文・技術文書など、信頼できる資料で主な事実を裏付けられるか |
| 映像化のしやすさ | 「見えない部分」を CG で見せる価値があるか。1 カット 1 情報に分解できるか |
| 面白さ | 冒頭 3 秒で「えっ？」と思わせる問いを立てられるか。途中に理解の転換があるか |
| 独立性 | 既存の動画と分野・CG 手法・掛け合いの型が重複しすぎないか |
| 安全性 | 事故・医療・災害など、誤解が実害につながるテーマでは特に慎重に扱う |

企業の内部情報に依存するテーマ（例：特定チェーンの物流の詳細）は、公開資料で検証できる範囲に絞るか、別の切り口に変える。

## 動画の基本仕様

### 映像
- 縦型 9:16（1080×1920 を想定）
- CG・3D アニメーション・図解が中心。内容に合わせて、シンプルな図解とリアル寄りの CG を使い分ける
- 比喩的な表現（光の粒、小包、キャラクター化など）には、必要に応じて「イメージ」「※模式図」の表示を入れる
- **明るく、色のコントラストのある画面**（第 2 話から。第 1 話は暗い背景が続き、平均輝度 36.6/255 だった）：
  - 場面ごとに明るい背景色（白・淡い水色・橙・黄など）を変え、暗い背景に文字を置くだけの画面にしない。
  - 主役の物体は実物に近い色（例：ご飯の白、海苔の深い緑、透明なフィルムの反射）で、アクセントに黄・橙を使う。
  - 文字は大きく、背景とのコントラストを取る。字幕は濃い帯の上に白と黄の文字。
  - 3 秒以上止まったままの画面を作らない。動きには意味を持たせる（カメラの寄り・層の分解・矢印など）。
  - 3D の物体は three.js（WebGL）で描く（`production/pilot_003/renderer.html`、`production/common/vendor/three.min.js`）。
- **全動画共通のエンディング**：本編の後に、W の声で「リバース。世界の仕組みを、はじめから。」と、専用の明るいエンディング画面（約 4〜5 秒）を必ず付ける。仕様は `docs/ENDING_SPEC.md`

### 音声
- オモテ（M）とウラ（W）の 2 人の掛け合い。声を明確に区別する。設定は `production/common/voices.json`、人物像は `docs/CHARACTER_GUIDE.md`
  - 第 3 話（pilot_006）以降（`v3`）：オモテ＝VOICEVOX:青山龍星（低い声、ノーマル／不機嫌／熱血／囁き）、ウラ＝VOICEVOX:冥鳴ひまり（第 1 話の女性の声に戻した）
  - 第 2 話（`v2`）：M＝青山龍星、W＝波音リツ。第 1 話（`v1`）：M＝白上虎太郎、W＝冥鳴ひまり
- 自然な日本語の口語

### 字幕
- スマートフォンで読みやすいサイズ。1 画面 2 行・1 行 16 文字程度までを目安
- 長文を一度に出さない。発話と同期させる
- 重要な単語・数値を強調する（台本では **太字** で指定）
- 数値や断定に条件が付く場合は、画面の端に注記（例：「※総務省『情報通信白書』で紹介された調査結果」）
