# 台本ルール（SCRIPT_RULES）

## 1. 基本構成

原則として次の流れにする。全動画を機械的に同じにする必要はないが、**理解しやすい論理の流れ** は必ず保つ。

| 記号 | 段階 | 目安 | 内容 |
|------|------|------|------|
| A | 冒頭のフック | 0〜3 秒 | M の思い込み・疑問と、W の短い返し。映像は「答えが気になる絵」 |
| B | 疑問の提示 | 〜8 秒 | この動画で解き明かす疑問を、字幕のタイトルとして明示する |
| C | 仕組みの可視化 | 中盤 | CG・図解で、現象を **順番に** 見せる（1 カット 1 情報） |
| D | 掛け合いによる理解 | 中盤 | M の疑問・勘違い → W の訂正・説明 |
| E | 意外性・理解の転換 | 後半の山場 | 直感だけでは気づきにくい重要ポイント |
| F | 結論 | 最後 10 秒 | 冒頭の疑問に明確に答える。必要なら短いオチ・余韻 |

- フックの例文（「データが空を飛んでる」「電波と妖精」）はそのまま使い回さない。
- 結論で、冒頭の M のボケを回収できると満足度が高い。

## 2. セリフ

- 音声合成にそのまま渡せる自然な話し言葉で書く（記号・括弧書き・注釈をセリフに入れない）。
- 1 セリフの目安：M は 25 文字以内、W は 40 文字以内（2 文まで）。
- 話速の目安：**1 秒あたり約 6 文字**（音声合成の標準速度・漢字かな混じりの概算）。
  `tools/check_scripts.py` が各行の必要話速を計算し、7.5 文字/秒を超える行を警告する。
- 不確実な情報は、言い方で示す：「〜と言われている」「〜ことが多い」「〜場合もある」。
- 数値を出すときは、単位と条件を省略しない（例：「海外との通信の約 99%」）。

## 3. 字幕

- 1 画面 2 行、1 行 16 文字程度まで。台本の「画面字幕」列では改行位置を ` / ` で示す。
- 強調する語は **太字**。
- セリフと字幕の内容は一致させる（字幕で言い換えるときも意味を変えない）。
- 条件・出典の注記は、字幕とは別の小さな注記として「※」で始める。

## 4. 映像・CG の指示

- 各行に「何を見せるか」を具体的に書く（カメラ、被写体、動き、色分け）。
- **比喩・演出の CG** には `［比喩］` を付け、必要なら画面に「イメージ」と表示する。
  例：パケットを小包として描く、電波を波紋として描く。
- 実在の企業ロゴ・商品パッケージをそのまま再現しない（汎用デザインにする）。
- 映像の指示とセリフが食い違わないようにする（自己レビューで確認する）。

## 5. 台本の書式

`templates/script_template.md` をコピーして使う。台本表は次の 6 列で固定する
（ツールが読み取るため、列の順番と見出しを変えない）。

| 時間 | キャラクター・音声 | セリフ | 映像・CGの指示 | 画面字幕 | 事実確認ID |
|------|------------------|--------|---------------|----------|-----------|

- 時間は `0:00-0:04` の形式（開始-終了、半角ハイフン）。
- キャラクターは `M` / `W` / `SE`（効果音）/ `—`（無音・映像のみ）。
- 事実確認 ID は `FACT-01` 形式。複数あるときは `FACT-01, FACT-03`。冗談・演出のみの行は `—`。
  冗談のうち、事実と誤解されうるものには `JOKE` と書き、事実確認リストの「冗談・演出」欄で扱う。

## 6. ファイル構成（1 本ごと）

```
scripts/pilot_00N/
├── script.md      # 1. 基本情報 / 2. フック / 3. 完全な台本
└── fact_check.md  # 4. 事実確認リスト / 出典一覧 / 事実と演出の区別
reviews/internal_review/pilot_00N_review.md     # 5. 自己レビュー結果
reviews/chatgpt_review/pilot_00N_chatgpt_review.md  # 6. ChatGPT 向け（ツールで自動生成）
```
