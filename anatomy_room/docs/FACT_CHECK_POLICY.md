# 事実確認ポリシー（FACT_CHECK_POLICY）

本プロジェクトでは、映像の面白さと同じくらい事実の正確性を重視する。

## 1. 情報調査

- 信頼できる一次資料・公的機関の資料を優先する（官公庁、法令、規格、RFC などの技術仕様、大学・研究機関、学術論文、特許公報）。
- 次点：業界団体・自治体・メーカーの技術資料、百科事典。
- 報道・解説記事・ブログは補助的に使い、単独の根拠にする場合は QUALIFIED 以下にする。
- **検索結果のタイトルだけで事実を断定しない。**
- 複数の説明がある場合は、その違いを記録する。
- 情報が不足している場合は、推測で埋めずに不足を明示する。

## 2. 確認方法の記録（必須）

各出典に、どうやって内容を確認したかを必ず書く。

| 確認方法 | 意味 |
|---------|------|
| `本文確認` | 資料の本文を直接開いて読んだ |
| `検索抜粋` | 検索ツールが返した、その資料の要約・引用抜粋で確認した（本文は開けていない） |
| `数学的導出` | 定義・公理から自分で導出し、他の資料の説明とも一致することを確かめた |
| `未確認` | 存在は知っているが内容を確認できていない（根拠としては使わない） |

**実際に確認していない URL や資料を、確認済みとして記載してはいけない。**
パイロット 5 本の調査は、すべて `検索抜粋` または `数学的導出` で行った（理由は `RESEARCH_ENVIRONMENT.md`）。

## 3. 事実と演出の区別

各シナリオについて、台本の要素を次の 5 つに分けて記録する（`fact_check.md` の「事実と演出の区別」表）。

1. **検証可能な事実** — 出典で裏付けられる主張
2. **事実に基づく説明** — 事実を簡略化・言い換えた説明（簡略化で失われたものを注記する）
3. **キャラクターの冗談** — 事実として受け取られないように、訂正・オチで回収する
4. **映像上の比喩・演出** — 現実そのものと誤解させない（必要なら「イメージ」表示）
5. **不確実な情報・条件付きの説明** — 言い方（「〜と言われている」）と注記で条件を示す

## 4. 出典管理

各出典について、次を記録する。

- 出典名 / 発行元 / URL
- 確認方法（上の表）
- 確認した主張
- どのセリフ・説明を支えるか（FACT ID）
- その情報の限界や注意点

## 5. 検証結果のラベル

### 主張ごと

| ラベル | 意味 |
|--------|------|
| **VERIFIED** | 出典の記述（`検索抜粋` を含む）で、主張を直接確認できた |
| **QUALIFIED** | 条件・注意点を付ければ使える（例：地域差がある、二次資料のみ、簡略化している） |
| **UNVERIFIED** | 根拠が不十分で、追加調査が必要。台本では使わないか、使うなら言い方で不確実さを明示 |
| **INCORRECT** | 誤りが確認された。台本から削除・修正する |

`検索抜粋` による VERIFIED は「本文確認」より弱い。公開前の最終確認で、本文を人が確認することを推奨する。

### シナリオごと

| 判定 | 条件 |
|------|------|
| **PASS** | 外部レビューに提出可能。台本に INCORRECT がなく、UNVERIFIED の主張を断定していない |
| **NEEDS_REVISION** | 修正が必要な箇所が残っている |
| **HOLD** | 動画の核となる事実を確認できず、採用保留 |

**PASS は絶対的な正確性を保証する意味ではない。**

## 6. 自己検証（台本を書いた後の別工程）

台本を書き終えたら、執筆とは別の工程として次を確認する。

- [ ] 科学的・技術的な誤りがないか
- [ ] 因果関係を取り違えていないか
- [ ] 数字や単位が正しいか
- [ ] 簡略化しすぎて誤解を生まないか
- [ ] キャラクターの冗談が事実と混同されないか
- [ ] 映像の指示とセリフが一致しているか
- [ ] 出典が実際に主張を裏付けているか（「確認した主張」と台本のセリフを突き合わせる）
- [ ] 視聴者が誤った結論を導かないか
- [ ] 断定してよい強さか（「必ず」「絶対」「すべて」を使っていないか）

問題を見つけたら台本を直し、「修正した箇所」に記録する。検証できない点を無理に「問題なし」としない。
