# リバース標準制作ルール（REVERSE STANDARD RULES）

> 版：**v2**（2026-10-27、ユーザーの指示「制作ルールの更新」：①ビートのあるテクノ BGM ②冒頭 3 秒のフック最優先 ③左上の固定ロゴを削除 ④CG などの注記は必要最小限 ⑤語尾が上がる問題の改善）。v1（同日「標準テンプレートの記憶と固定」）は `templates/versions/REVERSE_STANDARD_RULES_v1.md`。
> **設定の実体**：`production/common/standard.py`（新しい回の制作設定の既定値）・`voices.json` の `v7`・`music.py` の `tech_drive`・`stage.js`（ロゴの切り替え）・`tools/video_qa.py`（冒頭 3 秒の検査）・`pipeline.py`（文末の処理と検査）。
> **参考作品**：`production/pilot_010/reverse_010_inaccessible_rail.mp4`（「世界の果てに、空を飛べない小さな鳥がいる」88 秒）。制作データは同フォルダ、自己レビューは `reviews/internal_review/pilot_010_review.md`。
> **優先順位**：①その回のユーザーの個別指示 → ②このルール → ③`MASTER_VIDEO_TEMPLATE.md` ほか既存の docs。ただし CLAUDE.md の「絶対に守ること」（制作開始条件・課金禁止・未確認を確認済みと書かない・投稿はユーザーの指示まで行わない・共通エンディング）は常に守る。
> 新しい動画の指示が来たら、このルールを**既定値**として黙って適用する。毎回長く説明し直さない。指定のない項目はこのルールのまま。

## 1. コンセプト

日常の不思議・科学・歴史・自然・テクノロジーを、**一つの疑問を解き明かす物語**として見せる。知識の羅列にしない。

- 視聴者に「なぜ？」「どうして？」と思わせ、映像で直感的に分からせる。
- 科学的な根拠を大切にし、専門知識がなくても分かる言葉にする。
- 知的好奇心とエンタメを両立し、最後に発見・驚き・考える余地を残す。
- 全体の雰囲気：**知的で、少しミステリアス**。科学ドキュメンタリーの信頼感と、現代的なテクノロジー感。

## 2. 映像

| 項目 | 標準（維持） | 題材で変える |
|---|---|---|
| 色調 | 暗め：黒・濃紺・青・暗いグレー。アクセントはシアン／アイスブルー（#8FDCFF 前後）。**暗さが目的ではない**：被写体と文字がはっきり見えること（参考作品の本編の平均輝度 約 55/255、最低 29） | 自然・生物の回は緑・茶などの自然色を足す。歴史の回は重みのある色など |
| 表現 | 3DCG 中心。地球・地形・建造物・生物・分子・DNA などで説明対象を見せる。被写界深度・霧・リムライト・周辺減光・細かい粒子 | 何を 3D で作るか |
| カメラ | 意味のある動きだけ：接近（ドリー）・俯瞰・回り込み・マクロ。位置関係と変化が分かるように | 動きの種類・速さ |
| 禁止 | 子ども向け番組のような明るすぎる演出。意味のない派手なエフェクトやカメラ移動。白い閃光での場面転換（短い暗転でつなぐ） | — |
| 注記（v2） | **必要最小限**。判断基準は「注記があるか」ではなく「その注記が本当に必要か」。下の「注記のルール」 | 必要な注記の場所と回数 |
| ロゴ（v2） | **左上の固定ロゴは出さない**（`standard.py` の `"logo": False`）。ロゴのための余白も取らない。演出として個別に必要な回だけ `"logo": True` | ロゴを使う演出をするか |

### 注記のルール（v2）

- 一般的な CG 表現・通常の演出には注記を付けない。同じ注意書きを繰り返さない。すべてのカットに「※再現CG」を出さない。
- 注記を残すのは次の場合だけ：
  - 実際の映像・記録映像と誤認されるおそれが高い場合（写実的な生物・事件・人物の再現など）
  - 観察映像と説明用の再現 CG を区別する必要がある場合
  - 理解や安全に関わる重要な注意がある場合
  - 法令・プラットフォームの規定・権利関係で表示が必要な場合
- 必要な場合も、適切な場所に必要な回数だけ（例：再現 CG の生物が最初に出る場面で 1 回、短く）。必要な表示まで消さない。
- 参考作品 pilot_010 は注記が多すぎた（「※再現CG」を鳥・翼・オープニング・結びの場面ごとに出し、「※DNAのらせんはイメージ」「※経路の線はイメージ」「※一部の例」「※船の影はイメージ」も表示）。v2 の基準なら、写実寄りの鳥が最初に出る場面での 1 回で足りる。

- **オモテを出す場合**：顔のない、もちもちした人型（`production/common/stage.js` の `mochi3D`、`docs/CHARACTER_GUIDE.md` v3.2）。目・口などは一切つけず、感情は体の動きと汗のしずくで見せる。
- 色調・表現は固定のフィルターではない。題材に合う映像を優先しつつ、シリーズの統一感を保つ。

## 3. 構成（標準の 5 段）

| 段 | 内容 | 参考作品での例 |
|---|---|---|
| 1. フック（最初の 3 秒・**最重要**） | 下の「冒頭 3 秒のルール」。**この疑問を最後まで追う** | v2 の基準では弱い例：「世界の果てに、空を飛べない小さな鳥がいる」＋灰色の崖が 2 秒（鳥は 0.5 秒だけ）。強くするなら「この鳥、海を越えてきたのに飛べない。」のような矛盾を 1 秒目に、鳥の姿と一緒に |
| 2. 対象の紹介 | 基本情報を短く。データの羅列ではなく、珍しさが伝わる映像で | 地球 → 南大西洋 → 島 → 崖 → 草の根もと → 鳥（カメラが近づき続ける） |
| 3. 背景・仕組み | なぜ起こるか、何が分かっているか。映像は理解を進める役 | DNA の研究・祖先・到達の時期・小さな翼 |
| 4. 核心 | 「そういうことだったのか」と思える事実。小出しにしても引き延ばさない | 島で飛ぶ力を失う例は何度も／一つの理由では決めつけられない／ネズミもネコも入ったことがない |
| 5. 余韻 | 冒頭の疑問と結び、最も印象に残る事実で締める。根拠のない感動の言葉・推測を足さない | 「その足元には、ここでしか出会えない命がいる」 |

最後に共通エンディング（`docs/ENDING_SPEC.md`）を付ける。

### 冒頭 3 秒のルール（v2）

- 最初の 3 秒は、視聴者の興味を獲得するための最重要区間。**最初の 1 秒から**、映像か音で強い刺激を入れる。
- 前置き・挨拶・ロゴの表示に時間を使わない。ナレーションは 1 秒以内に始める（`standard.py` の `lead_in` 0.1 秒）。
- 意外な事実・強烈な疑問・常識を覆す情報（矛盾）から始める。3 秒以内に、続きを見る理由を示す。派手さだけでなく、本題と直接つながるフックにする。言い回しは毎回、題材に合わせて作る（同じ型を使い回さない）。
- ナレーション・映像・BGM・効果音を連動させる：BGM は 1 拍目から `doc_hook`、ナレーションの重要な言葉に効果音（`impact`・`hit` など、鋭くない音）、ビートに合わせた切り替え。
- 映像：被写体への急速な接近、強いコントラスト・大胆な構図、一瞬で意味が伝わる画。詰め込みすぎず、一番伝えたい情報が一瞬で伝わることを優先する。
- **完成前に冒頭 3 秒だけを切り出して確認する**：`python3 tools/video_qa.py pilot_NNN` が `qa/hook_3s.mp4`（音つき）と `qa/hook_strip.jpg` を作り、始まりの遅さ・無音・止まった画面を自動で調べる。最後は「初めて見る人が、この先を見たいと思うか？」で人が判断し、弱ければ冒頭を作り直す（自動検査に通るだけでは足りない。pilot_010 は自動検査をすべて通るが、v2 の基準では弱い）。

## 4. ナレーション・会話

- **標準はナレーション主体**：落ち着いた知的な男性の声（VOICEVOX:玄野武宏、`production/common/voices.json` の **`v7`**）。
- 重要な事実の前後に間を置く。専門用語には短い説明を添える。映像で分かることを冗長に読まない。詰め込まない・早口にしない。
- 読み間違いを確認する（参考作品では「現生」がゲンナマと読まれたため「いま生きている」に言い換えた）。

### 語尾のルール（v2）

- 自然な日本語のイントネーションを優先する。断定文の語尾を疑問文のように上げない。語尾を必要以上に伸ばさない。文中に意味のない間を入れない。すべての文を同じ抑揚にしない。疑問・驚き・強調など、文脈に応じた抑揚は残す。
- **原因と対策（実測）**：VOICEVOX は文末の「〜ている」の「いる」を独立したアクセント句（「オオワレテ'/イル'」）にし、低い「て」のあとで高く戻すため、語尾が上がって聞こえる。`v7` は合成のときに文末の「いる・いた・ある」を前の句につなげる（`pipeline.merge_final_aux`、行ごとに `"merge_aux": false` で無効）。pilot_010 の 8 行で「て→いる」の変化は +0.8〜−0.3 → −0.3〜−3.3 半音、時間は変わらない。
- VOICEVOX 0.24 は**最後のモーラの音程・長さの指定を反映しない**（82.5 Hz を指定しても 101.7 Hz）。設定だけで直らない語尾は、**原稿を直す**：文を短くし、意味のまとまりで区切る。上がりやすい終わり方（例：「〜になりうる」）は言い換える。読点は意味の切れ目にだけ打つ（読点の位置に間が入る）。
- 合成後は `qc_report.md` の「文末の音程」を見る（最後のモーラが +1 半音超、または文末の短い句へ +0.5 半音超の行を一覧にする）。挙がった行と、重要な文の語尾は耳でも確認する。
- **キャラクターの会話を使う回**（ユーザーの指定、または題材に合う場合）：オモテ／ウラの設定（`docs/CHARACTER_GUIDE.md`）を守る。発言が直前の発言・映像と論理的につながること、説明の応酬にしないこと、同じ情報を繰り返さないこと。キャラクターを使わない回を、無理に会話形式にしない。

## 5. 音

| 項目 | 標準 |
|---|---|
| BGM（v2） | **ビートを感じるテクノ／エレクトロニック／インダストリアル**：`music.py` の **`tech_drive`**（124 BPM、ニ短調。4 つ打ちのキック、うねるベース、金属的な打音、低いうなり）。知的・近未来的で、ミステリアスな空気は残す。**静かなアンビエント主体にしない**（参考作品の `tech_deep` の ambient／pulse は v2 では静かすぎる）。冒頭 1 拍目から存在感を出す（`doc_hook`）。展開でリズムと密度を変える：`doc_drive`（解説の基本。キックとベース、和音なし）→ `doc_build`（発見へ）→ `doc_break`（2〜4 秒の引き）→ `doc_peak`（核心）→ `doc_outro`。音量を上げるだけで存在感を出さない（低音・リズム・音色・展開で出す）。BGM は映像のテンポと緊張感を支える要素：場面の切り替え・発見の瞬間とモードの切り替えをそろえる |
| 効果音 | 柔らかい音色（`sfx_bank: "soft"`）。低音・短いクリック・柔らかい電子音・空間的な音。自然の回は波・風・草などの自然音。**鋭い高音・大音量・不快な繰り返しは使わない**。「印象に残る」と「不快」を混同しない。重要な場面だけに絞る |
| 実在の音 | 本物か確認できない鳴き声などは使わない（別の種の声を本物のように使わない） |
| バランス | ナレーションが主役。BGM はダッキング、仕上がり −14 LUFS 前後。ナレーションの帯域（1〜4 kHz）に BGM を重ねない（`tech_drive` の解説モードは和音・アルペジオなし。pilot_010 の声で試した実測：BGM の 1〜4 kHz は声より 33 dB 低い、全体のラウドネスの差 0.1 dB で声の大きさは変わらない）。ナレーション・BGM・効果音の音量を `qc_report.md` で確認する。スマホのスピーカーは 150 Hz 以下がほとんど出ないので、実機でビートが聞こえるかも確認する |

## 6. 事実確認

`docs/FACT_CHECK_POLICY.md` に従い、制作の前に `scripts/pilot_NNN/fact_check.md` を作る。

- 情報源の優先順位：①査読付き論文 ②大学・研究機関・公的機関 ③専門家の解説・専門書 ④信頼できる報道 ⑤その他。可能な限り一次資料。
- 数値・年代・地名・学術的な主張を確認する。出典の記述と、そこからの解釈を分ける。仮説・推定を確定として扱わない。因果が証明されていなければ断定しない。見解が分かれる点は考慮する。
- 確認できない情報は補わない。存在しない研究・論文・引用・数値を作らない。
- 確認方法を正直に書く（この環境では多くが**検索結果の抜粋**。本文を読めていないものは「確認済み」と書かない）。
- 完成後に整理するもの：動画内の重要な主張・出典・確定と推定の区別・直すべき表現・公開前の注意点。

## 7. テロップ・画面表示

`docs/TEXT_QUALITY.md` と `templates/VIDEO_QA_CHECKLIST.md` に従う。

- はみ出し・枠からの飛び出し・文字切れ・重なり・誤字脱字・文字化けをゼロにする（一つでも残れば完成にしない）。
- スマホの縦画面で読める大きさとコントラスト。フォント・色・大きさを統一。
- 重要な情報を画面端や YouTube Shorts の UI（右側のボタン列・下の説明欄）の位置に置かない。
- テロップの内容はナレーションと一致させる。**字幕と同じ文を、別の文字カードで重ねて出さない**。

## 8. テンポ・長さ

- 長さは題材で決める。目安は **60〜120 秒**（参考作品は 88 秒）。短さより、最後まで興味を持って理解できることを優先する。
- 冒頭はテンポよく。重要な発見の前後には短い間を置いてよい。同じ映像を理由なく長く映さない。間延び・繰り返しを避ける。
- 尺は実際の音声合成で測る（`tools/measure_tts.py`）。上限は `lines.json` の `max_duration` に書く。

## 9. 完成前の品質チェック

自動検査（`textcheck`・`qc_report.md`・`python3 tools/video_qa.py pilot_NNN --sheets`）のあと、**1 秒ごとの全コマを目で見る**。重大な問題があれば完成扱いにせず直す。

- 冒頭 3 秒：`qa/hook_3s.mp4` を見て「続きを見たいか」。1 秒目に刺激があるか、3 秒以内に続きを見る理由があるか
- 構成：冒頭で引けているか／一つの疑問が通っているか／場面が自然につながるか／最後に発見が残るか
- 映像：色調と世界観の統一／理解の助けになっているか／不自然な動き・破綻（浮く・埋まる・見切れる・何も映らないコマ）がないか／ナレーションと一致しているか
- 音：BGM にビートと存在感があるか（静かすぎないか）／軽すぎないか／耳障りな高音がないか／音量／ナレーションが明瞭か／**語尾が不自然に上がっていないか**（qc_report の「文末の音程」と耳）
- 画面：左上にロゴが出ていないか／注記が必要最小限か
- テロップ：正確に表示されているか／はみ出し・誤字・文字化けがないか／スマホで読めるか
- 事実：根拠があるか／推定と確定を分けているか／誇張がないか

### 参考作品の制作で得た注意点（再発させない）

- **全編を書き出す前に、全場面の静止画（`render_frames.js --stills`）で確認する**。この環境の書き出しは約 2 時間かかり、映像を 1 か所直すと全場面の書き直しになる。
- 単発の静止画は、前のコマの状態を引き継がないように、各場面で表示・非表示を毎回設定する（鳥が消えた不具合）。
- 地形：真上からの投影の模様は垂直な崖で縦の筋になる → 崖には画素ごとの地層の模様。草地が青い光と霧で海に見えることがある → 草の色と反射のない材質。
- 被写界深度は、全体をぼかした下地の上に焦点の層を重ねる（切り出すと境目に帯が出る）。
- 1 本のカメラの動きで大きく振り返ると、途中で空や海しか映らないコマができる → 2 カットを短い暗転でつなぐ。
- GLSL では `flat`・`patch` などの予約語を変数名に使わない。

## 10. 維持するもの／題材で変えるもの

| 原則として維持する | 題材ごとに変える |
|---|---|
| 知的でミステリアスな世界観 | 動画の長さ |
| 暗めでテクノロジー感のある色調（見やすさ優先） | カメラワーク |
| 冒頭で疑問を出し、最後まで追う構成 | 色調の細部（自然色・歴史の色など） |
| 映像と説明の連動 | BGM・効果音の種類 |
| 科学的な事実を物語として伝える姿勢 | キャラクターを使うか（会話形式か、ナレーションか） |
| 自然で聞き取りやすい声（語尾を上げない） | 説明の順序 |
| ビートのあるテクノ BGM・耳障りにならない効果音 | 情報量 |
| テロップの正確さと読みやすさ | 締め方 |
| 冒頭 3 秒のフック（切り出して確認） | フックの言い回しと映像 |
| 左上のロゴなし・注記は必要最小限 | 必要な注記の場所 |
| 公開前の事実確認・全編の目視確認 | — |

## 11. 新作での使い方

1. 新しい動画の指示を受けたら、まずこのファイルを読み、指示にない項目はすべてこの既定値で決める。
2. `templates/VIDEO_PRODUCTION_PROMPT.md` の項目に沿って、その回の可変項目（長さ・題材の色・カメラ・音・キャラクターの有無など）を決める。
3. 参考作品の作り方を土台にする：`production/pilot_010/`（`lines.json`・`renderer.html`）と共通部品（`common/pipeline.py`・`stage.js`・`music.py`・`voices.json`）。**制作設定は `production/common/standard.py` の `standard.config({...})` で作り、`lines.json` の `"voices"` は `"v7"` にする**（ロゴなし・tech_drive・やわらかい効果音・冒頭 0.1 秒で話し始める、が既定値で入る）。参考作品の renderer.html を写すときは、注記（uiNote）を v2 の基準で必要なものだけに減らす。
4. 事実確認 → 台本（フックと語尾を特に見直す）→ 音声合成（qc の「文末の音程」）→ 静止画で全場面確認（冒頭 3 秒は特に）→ 全編の書き出し → 自動検査（`video_qa.py` の冒頭 3 秒を含む）＋冒頭 3 秒の切り出しの確認＋全コマ目視 → 報告（保存先・変更点・確認したこと・制約）。
5. 個別の指示がこのルールと違うときは、個別の指示を優先する。その指示を今後の標準にしたいとユーザーが言った場合は、このファイルの版を上げて書き換える（旧版は `templates/versions/` に残す）。
