### 4. 事実確認リスト

#### FACT-01
- **主張**：スマートフォンから最初につながる区間（スマホ ⇄ 携帯電話の基地局、またはスマホ ⇄ Wi-Fi ルーター）は電波（無線）で通信する。
- **台本中の該当箇所**：「半分正解」、「電波で飛ぶのは、ふつうはスマホから近くの基地局や、Wi-Fiのルーターまで。」
- **出典**：S1, S2
- **検証結果**：QUALIFIED
- **注意点**：携帯電話について、スマホの電波を最寄りの基地局が受信するという説明は抜粋で確認できた。Wi-Fi が無線 LAN であることは一般的な事実だが、今回の調査では個別の出典を取っていない。また、基地局どうしを無線で結ぶ区間（マイクロ波回線など）や、衛星回線を使う例外もあるため「ほぼ」「基本的に」の範囲の説明である。台本は「電波で飛ぶのは〜まで」と言い切っているが、一般的な構成の説明としては妥当と判断した。
- **修正が必要か**：不要（ChatGPT に表現の強さを確認してもらう）

#### FACT-02
- **主張**：基地局の先は、光ファイバーなどの有線のケーブル網でデータが運ばれる。
- **台本中の該当箇所**：「残りはほとんどケーブルの中。ときには海の底。」、「そこから先は、地下や電柱のケーブルの中を、光になって走っていく。」
- **出典**：S1, S2
- **検証結果**：QUALIFIED
- **注意点**：総務省資料に、基地局と携帯電話交換局を光ファイバで結ぶ構成（光基地局方式）の図があることを抜粋で確認した。ただし抜粋がどの PDF 由来か特定できていない（S1 の注記参照）。ケーブルは地下だけでなく電柱の上（架空）を通る区間も多い。初稿の「地面の下のケーブル」は自己レビューで「地下や電柱のケーブル」に修正した。
- **修正が必要か**：修正済み（自己レビューで「地下や電柱のケーブル」に変更）

#### FACT-03
- **主張**：インターネットでは、データを小さな単位（パケット／IP データグラム）に分けて送り、それぞれに宛先などの情報（ヘッダ）が付いている。
- **台本中の該当箇所**：「小さく切り分けるの。パケット、小分けにした荷物ね。」、「一つ一つに宛先のラベル。届け方によっては、順番の番号も付く。」、「海外宛てならね。切り分けられた魚だけど」
- **出典**：S3
- **検証結果**：VERIFIED
- **注意点**：RFC 791 は、IP の役割を「アドレス（宛先）」と「分割（フラグメンテーション）」とし、ヘッダのアドレスでデータグラムを宛先へ届けると述べている（抜粋で確認）。「番号」は IP ではなく TCP の **シーケンス番号**（FACT-06）。台本では 1 枚のラベルに宛先と番号をまとめて描くが、実際には別の層（IP ヘッダと TCP ヘッダ）の情報である。入門向けの簡略化として許容範囲と判断。
- **修正が必要か**：不要

#### FACT-04
- **主張**：途中のルーターは、パケットの宛先を見て、経路表（ルーティングテーブル）にもとづいて次の転送先を選び、隣へ渡す。これを繰り返して宛先に届く（ホップバイホップ）。
- **台本中の該当箇所**：「途中のルーターって機械が、ラベルを見て、次はあっちって隣へ渡すの。」、「バケツリレーね。」
- **出典**：S3, S6
- **検証結果**：VERIFIED
- **注意点**：JPNIC の「インターネット 10 分講座：経路制御」は、ルーターが宛先ネットワークの方向を経路表で判断して転送する仕組みを説明している（抜粋で確認）。「バケツリレー」は比喩。
- **修正が必要か**：不要

#### FACT-05
- **主張**：(a) パケットは途中で失われることがある（混雑でルーターの待ち行列があふれると捨てられる等）。(b) IP 自体は届く順番を保証せず、仕組みとしてはパケットごとに別の経路を通りうる。(c) ただし実際のネットワークでは、同じ通信（フロー）のパケットは同じ経路に載せる設計が一般的。
- **台本中の該当箇所**：「混んでたりすると、途中で消えることもある。」
- **出典**：S3, S4, S7, S8
- **検証結果**：QUALIFIED
- **注意点**：(a) RFC 2309 は、待ち行列が満杯になると到着したパケットを捨てる方式（テールドロップ）を説明している。RFC 9293 も TCP の信頼性を「パケットの損失の検出と再送」と説明しており、損失が起きる前提である。(b) RFC 791 は、信頼性・順序制御を上位（TCP など）に任せると述べている。(c) RFC 2991 は、パケットを別々の経路に分けると順番が入れ替わり TCP に悪影響があるため、ハッシュによってフローごとに同じ経路を選ぶ方式を説明している。「同じ道を通ることが多い」はこの設計にもとづく言い方で、統計的な割合は確認していない。
- **修正が必要か**：不要（「多い」という控えめな表現にとどめている）

#### FACT-06
- **主張**：TCP では、受信側が受け取ったことを確認応答（ACK）で知らせ、確認が来ないデータは送信側が再送する。データには順番を表す番号（シーケンス番号）があり、受信側は順番どおりに並べてアプリに渡す。
- **台本中の該当箇所**：「届け方によっては、順番の番号も付く」、「多くの通信では、受け取る側が『届いたよ』って返事する。来ない分は、送り直すの。」、「届いた荷物は番号順に並べ直して、元のメッセージに戻すの。」
- **出典**：S4, S5
- **検証結果**：QUALIFIED

#### 修正した箇所（自己検証で直したもの）

1. **冒頭の W**：「残りは、ほぼ地面の下と海の底」→「残りはほとんどケーブルの中。ときには海の底」。
   国内のやり取りでは海底を通らないことが多いのに、「ほぼ…海の底」だと大半が海底を通るように聞こえるため。
2. **0:15 の W**：「地面の下のケーブル」→「地下や電柱のケーブル」。日本では電柱の上を通る区間も多いため。映像も地中と電柱の両方を見せる指示に変更。
3. **0:52 の W**：「返事がない分は送り直してもらうの」→「返事が来ない分は、送る側が送り直すの」。
